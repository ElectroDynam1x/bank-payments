# Учебный стенд

Стенд воспроизводит на одной машине закрытый контур: узлы кластера не обращаются в интернет,
образы берут из внутреннего реестра, доступ к API кластера и к реестру защищён TLS.

| Узел стенда | Адрес | Назначение |
| --- | --- | --- |
| `registry` | 10.10.0.5 (`registry.bank.local:5000`) | Реестр образов, TLS, вход по паролю |
| `git` | 10.10.0.6 (`git.bank.local:3000`) | Gitea: репозиторий и конвейер CI/CD |
| `lb` | 10.10.0.10 (`payments.bank.local`) | Балансировщик TCP перед шлюзами кластера |
| `prod-swarm-01` | 10.10.0.11 | Управляющий узел Swarm, шлюз, приложение |
| `prod-swarm-02` | 10.10.0.12 | Управляющий узел Swarm, шлюз, приложение |
| `prod-swarm-03` | 10.10.0.13 | Управляющий узел Swarm, приложение, том СУБД |

Узлы кластера запущены в контейнерах `docker:dind`. У каждого узла свой демон Docker,
поэтому кластер ведёт себя как три отдельных сервера: узел можно остановить и проверить,
что сервис продолжает отвечать.

## Порядок развёртывания стенда

```bash
stand/up.sh                                             # сеть, реестр, узлы, кластер, балансировщик
stand/create-secrets.sh bank-stage .stand/pki .stand/secrets/bank-stage_demo_password
stand/create-secrets.sh bank-prod  .stand/pki .stand/secrets/bank-prod_demo_password
```

После этого версию можно развернуть вручную (`deploy/scripts/deploy.sh`) или через конвейер.

## Файлы

- `up.sh` создаёт стенд;
- `create-secrets.sh` создаёт секреты контура в хранилище кластера;
- `lb.conf` содержит настройки балансировщика;
- `dev-secrets.sh` готовит секреты для локального запуска через Docker Compose.

## Особенность стенда

В ядре виртуальной машины стенда нет модуля IPVS, поэтому встроенная балансировка Swarm
по виртуальному адресу сервиса и сеть маршрутизации `ingress` недоступны. Сервисы работают
в режиме `endpoint_mode: dnsrr`, порт шлюза публикуется в режиме `host`, а запросы между
репликами распределяет nginx по записям DNS кластера. Такая схема применяется и там,
где перед кластером уже стоит внешний балансировщик.
